# ADR 0081: Accept authentic pending post-merge workflow registration without granting qualification

**Status:** Accepted
**Date:** 2026-11-09
**Supersedes:** The post-merge registration selector's assumption that the only nonterminal GitHub Actions statuses are `queued` and `in_progress`. It does not supersede the exact-head provenance, terminal-success, CodeQL zero-alert, Security, or package-integrity gates.

## Context

The accepted repository main advanced through three qualifying pull requests (#438, #439 and native Dependabot #437). PR #437, a one-file immutable `zizmorcore/zizmor-action` pin update, was regenerated by the native signed Dependabot service at head `8e28e7aa85d70a00dc9d6ccddf07299237c4fd33`; its exact-head CI, Security, CodeQL and governance checks passed before automatic merge to `main@d94e42baaa6d1dfd8bd09f66730d4b50b46d8628` on 2026-11-09.

The trusted dependency-governance controller's post-merge execution (run 42668803382, job 129339511370) started Security and CodeQL dispatches on the new main but failed while reading canonical workflow registration: `GovernanceError: exact-subject CodeQL run has invalid status: pending`. `pending` is a genuine GitHub Actions pre-queue state, not a scanner conclusion. Because the controller raised an exception **after** completing the merge transaction, it never dispatched exact-main CI for that accepted merge commit, even though the separately dispatched Security and CodeQL subsequently completed successfully. This is an observability and reconciliation failure, not a reason to treat the signed bot commit as unsafe or to override the required gates.

A concurrent CI run for the earlier `main@d23be255a85fb1ae3544e28e0720e835eb871023` failed its package-integrity bridge because its CodeQL run was cancelled when main advanced. That earlier failure was a correct fail-closed response to superseded proof, **not** authority to accept the cancelled analysis as green.

## Decision

The main-owned governance selector for *registration of post-merge workflows* accepts only canonical `pending`, `requested`, `waiting`, `queued`, `in_progress`, or `completed` statuses for runs matching the exact accepted-main SHA, workflow name/path, branch, event, unique positive run ID and positive run attempt.

For any **nonterminal** status, require `conclusion is None`; reject attempts to attach a premature `success`, `failure` or `cancelled` conclusion. For `completed`, require `conclusion == success`; a cancelled, skipped, timed-out, failed or missing terminal conclusion remains blocking. Unrecognized statuses, wrong branch/SHA/event, ambiguous duplicate runs, malformed IDs or contradictory conclusions remain fatal. A nonterminal registration receipt is **not** qualification evidence: it only confirms that GitHub accepted the dispatch so the controller can continue registering all required workflows, in strict Security → CodeQL → CI order.

Preserve existing independent exact-head native CodeQL, real scanner jobs, Security, `Package integrity`, signed Dependabot provenance, unchanged main/head leases, owner veto and review, protected CI gate, and merge receipt verification. Never fake, override or waive any status to rescue a failing run. The policy remains forward-compatible with GitHub's documented queue lifecycle while rejecting an unknown status rather than treating it as success.

## Consequences

The controller can now complete a post-merge dispatch sequence when the provider briefly reports `pending`, `requested` or `waiting`. A subsequently red workflow remains red and is subject to existing investigation; the registration receipt explicitly records its pre-terminal status rather than claiming all post-merge checks passed. This narrows a race between GitHub's workflow registration and scheduling without relaxing the qualification or merging authority.

The previously accepted PR #437's exact main received real successful CodeQL and Security dispatches but lacked CI because the old code had already failed; no retroactive green CI is inferred. The qualifying code fix must itself pass full exact-head PR CI/Security/CodeQL before merger, then the new main's own full push CI, CodeQL, Security, release integrity and governance outcomes must be observed. Future bot merges must show actual registration of all required workflows.

## Assurance impact

Lineage-and-salvage preflight: before creating this branch, latest accepted main was `d94e42baaa6d1dfd8bd09f66730d4b50b46d8628` (#437), and live branch enumeration returned **only main**, with zero open PRs and open issue #440 tracking the external Dependency Review HTTP 403 prerequisite. Previous relevant PRs #437, #438 and #439 are merged, their unique payloads **already accepted**, and their historical fix and Dependabot branches are absent. Prior publisher and governance alternatives #427/#429/#434/#435 are similarly already accepted or superseded. No divergent live or orphan branch with unique must-salvage content was found.

The original dependency-governance script blob is `6e549c7e7001e01685b95b85b01cc101a638ff58`; the existing trusted workflow definition is intentionally unchanged. Add adversarial self-test fixtures across all three required post-merge workflows proving each authentic nonterminal state is accepted only with a null conclusion, every contradictory status/conclusion pairing fails, unrecognized states fail, terminal non-success still fails, duplicate and foreign identity evidence fail, and dispatch ordering remains Security → CodeQL → CI. Preserve mandatory append-only semantic ADR and branch-history qualification.

## Non-claims

A pending, requested, waiting, queued or in-progress status proves **only successful registration**, not completion, security qualification, CodeQL zero alerts, supply-chain integrity or a safe merge. This change does not imply that the earlier cancelled CodeQL run or prior main CI failure was successful, and it does not enable GitHub dependency-graph comparison. Issue #440 remains separately open until actual change-aware review is verified, without fabricating access to the repository's administration settings.
